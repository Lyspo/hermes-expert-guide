Grouped by what you are trying to do rather than alphabetically. Where the
documentation disagrees with itself, both forms are given.

## Getting started

| Command | What it does |
|---|---|
| `hermes` | Start an interactive session |
| `hermes --tui` | The modern terminal interface |
| `hermes chat -q "…"` | One query, non-interactive |
| `hermes setup` | The full wizard. First run offers Quick, Full and Blank Slate |
| `hermes setup --portal` | Nous Portal OAuth, the one-command path |
| `hermes model` | Choose provider and model interactively |
| `hermes tools` | List and configure tools per platform |
| `hermes doctor` | Diagnostics. Always the first thing to run |

## Sessions

| Command | What it does |
|---|---|
| `hermes --continue` / `-c` | Resume the most recent session |
| `hermes -c "name"` | Resume by name — the newest in that lineage |
| `hermes --resume <id>` / `-r` | Resume by session id or title |
| `hermes sessions list` | List sessions |
| `hermes sessions browse\|export\|delete\|prune\|archive\|stats` | Manage the store |
| `hermes sessions rename <id> <title>` | Name one after the fact |
| `hermes insights --days N` | Token, cost and activity analytics |

## Skills

| Command | What it does |
|---|---|
| `hermes skills list\|browse\|search` | See what is installed or available |
| `hermes skills install <skill> [--force]` | Install. `--force` overrides a non-dangerous finding only |
| `hermes skills inspect\|check\|audit` | Look before installing |
| `hermes skills update [skill]` | Update; user-modified bundled skills are skipped |
| `hermes skills uninstall\|reset` | Remove or restore |
| `hermes skills tap add\|list\|remove` | Manage installation sources |
| `hermes curator status\|run\|pause\|resume` | The maintenance pass |
| `hermes curator pin\|unpin\|restore\|list-archived` | Protect or recover a skill |
| `hermes curator backup\|rollback` | Snapshot and revert a pass |

## Two things the documentation has not settled

**`hermes portal info` versus `hermes portal status|open|tools`.** The integrations page
documents the first; the CLI reference documents the second set. One of them will fail on
your machine, and knowing there are two candidates is faster than assuming a typo.

**`hermes login` / `logout` are superseded** by `hermes auth <provider>`.

## From the API server, because it is easy to miss

Bearer authentication is required on **all** deployments including loopback — there is no
localhost exemption. Server-side response storage is capped at **100 responses with LRU
eviction**, and file uploads are not supported.
