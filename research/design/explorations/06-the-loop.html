module 06 · the loop

A counter, a threshold, a fork.

Self-improvement is sold as a disposition — the agent notices what worked and gets better. What ships is three mechanical parts: a counter, a threshold, and a second agent that is forbidden from speaking to you.

The counter increments inside the tool-calling loop, once per API-call iteration. Not once per message. A single request that takes five round-trips advances it by five, so a long piece of real work can trip it twice.

module 06 · isolation

Four walls, all of them code.

The fork's toolset is cut to skills and memory. _persist_disabled is set and its handle to the session database is None. Any approval prompt it triggers is auto-denied. Its own nudge intervals are zero, so a review cannot spawn a review.

Nothing it produces re-enters your conversation. That absence prevents a named failure: without it, the review's own instruction would land in your session and the agent would read it back as an order.

module 04 · approvals

The gate that did not fire.

On a default install a recursive delete on a host path executed with no prompt at all. Under approvals.mode: smart an LLM risk-assesses and may auto-approve; only the hardline blocklist and your own deny globs are deterministic.
